# l432boot — STM32CubeIDE 工程

使用 STM32CubeIDE 导入本目录已有的 `.project`，工程名 `l432boot`。
无需配置 VS Code、CMake 或 launch.json。

**2026-10-28 验证基线：旧上位机连续升级三次并连接成功，升级中断后重刷及参数保留均经板上验证。**

## 构建和首次调试

1. CubeIDE：File → Import → General → Existing Projects into Workspace。
2. 选择本目录，导入 `l432boot`。如果已在工作区中，右键 Refresh 即可。
3. 选择 Debug 配置，执行 Project → Clean，再 Build Project。
4. 生成 `Debug/l432boot.elf` 和 `Debug/l432boot.bin`。
5. 连接 ST-LINK，右键工程 → Debug As → STM32 C/C++ Application。
6. 停在 main 后继续运行，或停止调试后复位板子，验证独立上电启动。

新增逻辑位于 `Core/Src/boot.c`，main.c 只在 USER CODE 中调用 `Boot_Run`。
`.cproject` 的 Debug、Release 均配置生成 BIN 的构建后步骤。
CubeMX 再生成后，应检查链接文件仍限制 Boot 为 32 KB。

## 当前布局

| 区域 | 地址 | 大小 |
|---|---|---:|
| Boot | 0x08000000–0x08007FFF | 32 KB |
| APP | 0x08008000–0x0801F7FF | 94 KB |
| 参数 | 0x0801F800–0x0801FFFF | 2 KB |

当前 APP 的链接起点和 SystemInit 向量表偏移已设为 0x08008000。
参数地址保持原样；Boot 只擦写 APP 区。整片擦除会丢失参数，维护时应选择区域擦除。

发布 APP 前必须重新构建，检查链接文件 `microFlow_cc_module/STM32L432KBUX_FLASH.ld`
和 `Core/Src/system_stm32l4xx.c` 的偏移一致。旧版从 `0x08000000` 链接的 BIN
不能用于本 Boot。BIN 不携带加载地址，YMODEM 由 Boot 固定从 `0x08008000` 写入。
不要将 Boot BIN、HEX 或 ELF 当作 APP BIN 发送。

首次 SWD 烧录 Boot ELF 自带地址；使用 Boot BIN 时显式指定 `0x08000000`。
日常升级只发送 APP，Boot 保持不变。重新生成 CubeMX 后检查 Boot 32 KB 限制、
USER CODE 中的 Boot_Run 调用、APP 的链接地址与向量偏移、BIN 构建后步骤。

## RS485 升级

- USART1：PA9 TX、PA10 RX、PA12 DE，高电平有效。
- 固定 9600 / 8N1，无流控；沿用生成的 8 MHz HSE bypass 和 80 MHz 系统时钟。
- 上电提示后 5 秒内发送小写 `abc`，进入菜单。
- 输入 `1`，看到发送提示后，用终端的 YMODEM 功能发送 APP 原始 BIN。
- 成功后复位，等待窗口结束后跳转 APP；APP 使用其保存的通讯参数。
- 失败留在菜单，再输入 `1` 可以重试；APP 明显无效时自动留在菜单。
- 提示文本及 CR/LF 与 ST_588 旧 Boot 的升级流程保持一致，包括菜单中的 `Porbe` 拼写、`Waiting  ...` 和成功时的文件名及字节数。
- 协议沿用旧 Boot：头包回复 ACK+C，数据包回复 ACK，第一次 EOT 直接回复 ACK，最终空头包回复 ACK。若主机等待 C，则接收超时后发送 C。
- 等待首个文件头时持续每约 2 秒请求一次 C，不再在约 20 秒后自动退出；发送 A/a 或双 CAN 可取消。传输开始后连续错误仍会退出并允许重试。
- APP 命令 7 只执行复位，随后仍需切换到 Boot 的串口参数并发送 abc。
- Boot 将 PA8 保持低电平，不输出阀门 PWM。

升级支持分包 CRC16、重传、长度和地址范围检查、写入回读；不保存版本、整包 CRC 或升级标记，不做备份和回滚。
下载中断后残缺 APP 可能通过入口检查；按约定重新上电命中 abc 后覆盖下载即可。
总线升级须在可控条件下确保只有目标设备进入接收，提示和 YMODEM 无设备地址。

## 旧上位机兼容约定

以下为接收端应答，数值为十六进制。提示文本的空格、拼写和 CR/LF 均属于兼容约定，
不能只为美化显示而修改。

| 上位机动作 | Boot 应答 |
|---|---|
| 上电 | `Press abc to interrupt ......` + `\r\n\n` |
| 5 秒内发送 `abc` | `  Download Image To the Porbe Internal Flash ----------- 1` + `\r\n\n` |
| 发送 `1` | `Waiting  ... ` + `\n\r`；等待约 2 秒后发送 `43`（C） |
| 文件头包（序号 0） | 校验长度并擦除 APP 后发送 `06 43`（ACK+C） |
| 正常数据包 | 写入并回读后发送 `06`（ACK） |
| 前一包重传 | 重发 ACK，不重复写入；头包重传回复 ACK+C |
| 数据包序号错误 | `15`（NAK） |
| 首次 EOT（04） | `06`（ACK）；不要求第二次 EOT |
| EOT 后等待超时 | `43`（C），请求最终空头包 |
| 最终空头包（序号 0） | 检查 APP 入口后回复 `06`（ACK），打印原版成功文本、文件名和有效字节数，约 1 秒后复位 |
| 发送 `18 18`（双 CAN） | `06`（ACK），打印取消提示并回菜单 |
| 等包起始字节时发送 `A` 或 `a` | 回复 `18 18`，打印取消提示并回菜单 |

包 CRC 为 CRC16/XMODEM（0x1021，初值 0），高字节先传；支持 128 B 与 1 KB 包。
首包前一直等待，首包后累计 6 次连续错误退出。错误/超时请求沿用旧版 C 应答。
本工程只提供下载菜单 1，不实现旧模板中的上传和修改 Flash 保护选项。

## APP 命令与启动边界

APP 命令 7 先清命令并复位，由 Boot 重新执行上电窗口。
自动保存不得覆盖显式命令，否则同一 Modbus 写操作会使复位命令失效。
APP 运行时通讯参数可能不同于 Boot，不能假定重启后仍沿用 APP 的串口参数。

入口检查仅验证 SRAM1 栈指针范围与 8 字节对齐、Thumb 复位向量及其所属 APP 区域。
未收完的固件也可能满足这些条件；恢复依靠上电 abc 入口。复位后的恢复流程不依赖
原 APP 可运行，不承诺自动运行旧版本或校验整个 APP 的完整性。
